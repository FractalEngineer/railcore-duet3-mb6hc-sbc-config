### Manage the DSF configuration from Git ###

DSF runs as the dedicated `dsf` account and uses `/opt/dsf/sd` as its live
virtual SD card. Do not use `chmod 777`, do not pull as root, and do not pull
while DuetControlServer is using the directory.

The update script preserves these DSF-generated files across pulls:

- sys/config-override.g
- sys/heightmap.csv
- sys/resurrect.g
- sys/eventlog.txt
- filaments.csv

It also backs up the active sys, macros, and filaments directories, refuses
unexpected local edits, validates that system G-code files are not blank,
restores the backup if deployment fails, and returns DCS to its previous state.

#### One-time repair of an existing checkout ####

Only do this while the printer is idle and all heaters are off:

sudo systemctl stop duetcontrolserver
sudo cp -a /opt/dsf/sd "/opt/dsf/sd_backup_$(date +%Y%m%d-%H%M%S)"
sudo chown -R dsf:dsf /opt/dsf/sd
sudo -H -u dsf git -C /opt/dsf/sd config core.fileMode false
sudo find /opt/dsf/sd -type d -exec chmod 2750 {} +
sudo find /opt/dsf/sd -type f -exec chmod 0640 {} +
sudo -H -u dsf git -C /opt/dsf/sd pull --ff-only
sudo test -s /opt/dsf/sd/sys/config.g
sudo test -s /opt/dsf/sd/sys/daemon.g
sudo install -o root -g root -m 0755 /opt/dsf/sd/scripts/update-dsf-config.sh /usr/local/sbin/update-dsf-config
sudo systemctl start duetcontrolserver

If any bootstrap command fails after DCS was stopped, run
`sudo systemctl start duetcontrolserver` before troubleshooting.

#### Routine update ####

Run this from any directory:

sudo update-dsf-config

The script asks for confirmation before interrupting DSF. For deliberate
non-interactive use, after independently confirming the printer is idle:

sudo update-dsf-config --yes

Backups are retained under `/opt/dsf/config-backups/`. Remove old backups
manually only after confirming the printer works correctly.

#### New installation ####

Only do this while the printer is idle and all heaters are off:

sudo systemctl stop duetcontrolserver
dsf_backup_dir="/opt/dsf/sd_backup_$(date +%Y%m%d-%H%M%S)"
sudo mv /opt/dsf/sd "${dsf_backup_dir}"
sudo install -d -o dsf -g dsf -m 0750 /opt/dsf/sd
sudo -H -u dsf git clone https://github.com/FractalEngineer/railcore-duet3-mb6hc-sbc-config.git /opt/dsf/sd
sudo -H -u dsf git -C /opt/dsf/sd config core.fileMode false
for runtime_file in config-override.g heightmap.csv resurrect.g; do
    if [ -f "${dsf_backup_dir}/sys/${runtime_file}" ]; then
        sudo install -o dsf -g dsf -m 0640 "${dsf_backup_dir}/sys/${runtime_file}" "/opt/dsf/sd/sys/${runtime_file}"
    fi
done
sudo install -d -o dsf -g dsf -m 0750 /opt/dsf/sd/gcodes
if [ -d "${dsf_backup_dir}/gcodes" ]; then
    sudo cp -a "${dsf_backup_dir}/gcodes/." /opt/dsf/sd/gcodes/
fi
sudo chown -R dsf:dsf /opt/dsf/sd
sudo find /opt/dsf/sd -type d -exec chmod 2750 {} +
sudo find /opt/dsf/sd -type f -exec chmod 0640 {} +
sudo install -o root -g root -m 0755 /opt/dsf/sd/scripts/update-dsf-config.sh /usr/local/sbin/update-dsf-config
sudo systemctl start duetcontrolserver

### Fix Default Keyring Popup ###

In terminal:

sudo apt update
sudo apt install seahorse

then run:

seahorse

In Passwords and Keys:

-Find Default Keyring or Login
-Right-click it → Change Password
-Enter its current password
-Leave the new password completely blank
-Accept the warning about storing passwords unencrypted
-Reboot
