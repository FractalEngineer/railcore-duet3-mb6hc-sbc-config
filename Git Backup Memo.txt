# On new setup:

### Change screen res to 1024 x 600 ###
https://forums.raspberrypi.com/viewtopic.php?t=14914

sudo nano /boot/config.txt

disable_overscan=1
hdmi_cvt=1024 600 60 3 0 0 0



### Manage the DSF configuration from Git ###

Start with a working DuetPi image. The installer supports a fresh DuetPi setup
or an existing Git-managed setup; it does not install Raspberry Pi OS or DSF.
Only run it while the printer is idle and all heaters are off.

#### One-command setup or update ####

No script has to be copied to the Pi. This one command downloads the public
bootstrap directly from GitHub and works for both installation and updates:

wget -qO- https://raw.githubusercontent.com/FractalEngineer/railcore-duet3-mb6hc-sbc-config/master/install.sh | sudo bash

The deployer asks for confirmation before stopping DCS. It then:

- Detects whether `/opt/dsf/sd` is already a Git checkout.
- Preserves the existing configuration and generated machine state.
- Moves a non-Git installation to a timestamped backup before cloning.
- Preserves `gcodes` plus DSF-managed `firmware`, `menu`, `scans`, and `www`
  directories without duplicating them.
- Runs Git as the dedicated `dsf` account.
- Validates that required system G-code files exist and are not blank.
- Restores the original directory automatically if migration fails.
- Makes files readable to normal login accounts but writable only by `dsf`.
- Restarts DCS if it was running before deployment.
- Installs `/usr/local/sbin/update-dsf-config` for later updates.

For deliberate non-interactive use, after independently confirming the printer
is idle:

wget -qO- https://raw.githubusercontent.com/FractalEngineer/railcore-duet3-mb6hc-sbc-config/master/install.sh | sudo bash -s -- --yes

#### Later updates ####

Either repeat the universal command above or use the installed updater:

sudo update-dsf-config

Backups are retained under `/opt/dsf/config-backups/`. Remove old backups
manually only after confirming that the printer works correctly.

To inspect Git directly, run it as the repository owner:

sudo -H -u dsf git -C /opt/dsf/sd status


### Legacy pin reassignment for the replaced Pi ###

The old Pi required this manual change because its normal transfer-ready GPIO
was damaged. Do not apply this to the replacement Pi or normal installations:

"TransferReadyPin": 24


### Fix Default Keyring Popup ###

In terminal:

sudo apt update
sudo apt install seahorse

then run:

seahorse

In Passwords and Keys:

-Find Default Keyring or Login
-Right-click it → Change Password
-Enter its current password
-Leave the new password completely blank
-Accept the warning about storing passwords unencrypted
-Reboot
